# FPGA Bring-up & Debug

> 这个技能解决的不是"某个工程的某个 bug"，而是**一类失败模式**：
> 现象模糊、证据不可信、改动互相污染、报告与事实脱节。
> 全套方法只依赖三样东西：**可复算的数字、可证伪的假设、可重放的日志**。

---

## 0. 一条不可让渡的原则

**没有数字，就没有根因。**

"计数器可能写错了"、"可能是时序问题"、"换个写法试试" —— 这些不是假设，是猜。
每条结论必须能写成一行算式或一个可观测信号，例如：

```text
同一帧 1080p，两个域两个答案，必须选"真正产生像素"的那个域：
  148.5 MHz 扫描侧：2,073,600 / 148.5e6 = 13.96 ms
  50 MHz 写侧   ：2,073,600 /  50.0e6 = 41.47 ms   ← 本工程瓶颈在这里
帧率被 60Hz VSYNC 量化：可取值 60/N = 60/30/20/15/12 …
若每帧耗时 41.47 ms（生成）+ 读卡 > 66.67 ms，就掉进 60/5 = 12 fps 档
```

如果你写不出这一行，说明还没到"提方案"的阶段，回到 §2 的 S1。

## 1. 何时用 / 何时不用

**用**：

- 板子上的画面、帧率、色彩、几何、菜单和预期不符；
- 仿真过了但上板不对（或反过来）；
- 需要在不改原件的前提下验证别人的工程；
- WNS/WHS 为负、资源超限、要实现/综合后需要 signoff；
- 需要给视频通路做带宽/缓冲/帧率的可行性预算；
- 要交付"能复现"的工程包：RTL + 仿真 + 报告 + bit + 上板记录。

**不用**：

- 纯软件/纯算法（没有时钟、没有复位、没有跨域）——用普通调试流程即可；
- 板子根本不启动（供电/下载链/器件选型）——先做硬件最小启动验证，本文档从"能下载、有时钟"开始；
- 只要求"帮我写个模块"——那是实现任务，不需要本循环。

## 2. 主循环：S0 → S5

```text
S0 基线      ── 冻结现场：快照、日志、版本、现象录像
   ↓
S1 预算      ── 把现象翻译成数字：时间、带宽、容量、延迟
   ↓
S2 假设      ── 列 3~5 条可证伪假设，按"能解释全部现象"排序
   ↓
S3 实验      ── 一次只验一条：TB / ILA / 删减版 RTL，成本从低到高
   ↓
S4 修复      ── 最小改动 + 双版本（保守/激进）+ 回归
   ↓
S5 沉淀      ── 报告、判据、失效条件、踩坑条目
```

### S0 基线（15 分钟，永远不要跳过）

| 动作 | 目的 | 命令/产物 |
|---|---|---|
| 给原件拍哈希快照 | 证明"我没动原件" | `python scripts/verify_manifest.py --root <proj> --save baseline.json` |
| 抄一份工作副本 | 所有改动只发生在副本 | `Copy-Item -Recurse proj proj_work` |
| 记录版本三元组 | 防止"烧的是旧 bit" | `RTL 最后修改时间 / bit 生成时间 / 本次 log 时间` |
| 固化现象 | 口头描述会漂移 | 录 10 s 视频或拍 3 张照；记下"哪一块、什么颜色、什么节奏" |

> **反例（真实发生）**：改了 RTL、只跑了仿真、烧的是修复前的 `.bit`，
> 于是连续三轮"修了没用"，真正原因是产物陈旧。基线里必须有版本三元组。

### S1 预算（本技能的核心，见 `references/timing-budget.md`）

把现象变成 4 个数字，缺一不可：

1. **时间预算**：一帧/一行要多久？`t = pixels / f_clk`（注意用**像素时钟**，不是系统时钟）。
2. **带宽预算**：源端每秒能吐多少字节？`B/s = f_sclk / 8 × 有效率`；目的端要多少？`W×H×Bpp×fps`。
3. **容量预算**：缓冲能撑多久抖动？`t_hold = buffer_bytes / (consume_rate - fill_rate)`。
4. **量化台阶**：如果帧率/分辨率来自分频或整数倍关系，列出所有**可能取值**
   （60/N：60/30/20/15/12/10…），实测值落在哪一档，就锁定了误差量级。

**判据**：预算算完，现象应该能"对上号"。
对不上，说明你漏了一级（通常是漏了消隐期、命令开销、或跨域握手延迟）。

### S2 假设（写成能被否定的句子）

每条假设必须包含：**预测**（如果成立，应观测到什么）+ **否证条件**（观测到什么就推翻）。

```text
H1 帧率被 VSYNC 分频卡在 12：预测 t_frame ∈ (66.67, 83.33] ms
   → 实测 OSD=12，且 66.67 < t < 83.33 → 成立
H2 SD 逐扇区命令开销占主导：预测把 CMD17 换 CMD18 后 t_read 降 >30%
   → 若换完只降 5%，H2 推翻，转查像素生成侧
```

排序规则：**能同时解释最多现象的那条排第一**；
"只解释一个细节、还要额外假设"的排后面。不要按"最容易改"排序。

### S3 实验（成本从低到高，能停就停）

| 手段 | 成本 | 适用 | 判据 |
|---|---|---|---|
| 静态核对（常量/位宽/连接） | 分钟 | 位宽截断、参数没生效、占位逻辑 | `scripts/rtl_const_check.py` |
| 单元 TB（模块级） | 十分钟 | 状态机、计数器、编解码 | `RESULT: PASS/FAIL` 结构化输出 |
| 分阶段 TB（可独立驱动的子链） | 小时 | 整机太大搭不起来 | 每阶段独立 PASS + 失败可定位到模块 |
| 集成/冒烟 TB（顶层） | 小时 | 上板前最后一关 | 复位释放→首帧出图→不卡死 |
| ILA 上板抓波形 | 半小时/轮 | 仿真复现不了（CDC、亚稳态、真实器件延迟） | 触发条件 + 期望序列 + 反例序列 |

**铁律**：一次只动一个变量。两个改动同时上，就没法把结果归因。

### S4 修复（最小改动 + 双版本 + 回归）

- **最小**：能在 3 行内解决，就不要重构整个模块；评审时"改动面"本身就是风险。
- **双版本**：保守版（只修 bug）+ 激进版（顺手优化），分别出 bit、分别记录指标。
  用户在现场往往没时间试错，双版本能把"回退"变成一次烧录。
- **回归**：修复后必须重跑 S3 里所有已通过的实验，并新增一条针对本 bug 的断言。
- **回退点**：动手前 `git init` 或复制目录；每轮结束能一句话说清"回到哪一版"。

### S5 沉淀（不写下来 = 没发生过）

报告的最小结构见 `assets/report_template.md`，硬要求：

1. 现象（可复现的描述 + 图/日志位置）；
2. 预算（S1 的四个数字）；
3. 假设与判决（哪条成立、哪条被证伪、证据是什么）；
4. 改动（文件 + 行 + 为什么这一行能修）；
5. 验证（仿真判据、时序/资源、上板记录）；
6. **失效条件**（什么情况下这个修复不再成立）。

## 3. 十条硬规则

1. **原件只读**。验证别人工程时，先哈希快照，再在副本上动手；结束时用哈希证明零改动。
2. **先算后猜**。算不出数字，就不许提修改方案。
3. **声明即行为**。`localparam`→`parameter`、位宽 `[24:0]`→`[25:0]`、`integer`→`reg [N:0]`，
   任何声明改动都按"可能改变上板行为"处理，必须单列一节说明。
4. **日志三段齐全**。`xvlog`（编译警告）/`xelab`（参数与展开）/`xsim`（运行结果）分别落盘，
   只留最后一段的日志不能作为证据。
5. **判据要有数值和比较符**。写"误差 ≤ 4/255"而不是"基本一致"；写"PASS"必须能追到断言。
6. **产物标版本**。每个 bit 对应哪次 RTL 改动、哪份报告，写一行；不确定就标"陈旧"。
7. **一次一个变量**。同一轮里改了两个地方，结论只能写成"二者之一"，不能写成根因。
8. **跨域单独审**。多 bit 跨时钟域不允许"直接打两拍"；同步器入口必须有 `false_path`，
   但 `false_path` 只加在同步器**入口**，不能盖住整条路径。
9. **失败要回退**。连续两轮"没变化"，停止改动，回到 S1 重算预算——大概率是模型错了。
10. **报告写失效条件**。没有边界的技术结论不可复用，也无法在下次被安全推翻。

## 4. 症状路由表

| 现象 | 第一嫌疑 | 先看哪里 | 详见 |
|---|---|---|---|
| 帧率低于目标且是整数档（12/10/7.5） | VSYNC 分频量化 | 帧预算 vs 分频表 | `timing-budget.md` §2 |
| 帧率低但不整档、随内容波动 | 源端带宽/命令开销 | 每帧字节数 × 命令开销 | `timing-budget.md` §3 |
| 画面整块右移/上移（切换后） | 写侧 FIFO 残留 + 偏移量未清 | `frame_sync` 是否 flush、`rd_off` 是否复位 | `symptom-playbook.md` §2 |
| 撕裂、上下半屏新旧不一 | 双缓冲换页时机 | 是否在 VSYNC 消隐期换页 | `symptom-playbook.md` §3 |
| 花屏/斜纹/彩色噪点 | 像素格式或时序相位 | RGB565/BGR、DE 极性、采样沿 | `symptom-playbook.md` §4 |
| 边缘/卷积模式出现规则点阵 | 窗口/行缓冲读地址步进 | 行缓冲深度与读指针 | `symptom-playbook.md` §5 |
| 文字/菜单错位、缺笔画 | 字库位宽或 OSD 混叠优先级 | 字模 ROM 位宽、alpha 混合 | `symptom-playbook.md` §6 |
| WNS 负得离谱（−4 ns 级） | CDC 同步器被当同步路径 | 第一条违例路径的起点/终点 | `cdc-and-signoff.md` §2 |
| WNS 勉强负 0.1~0.5 ns | 扇出/布局/时钟不确定性 | 违例路径类型 + 逻辑级数 | `cdc-and-signoff.md` §3 |
| WPWS 负、WNS/WHS 正 | OSERDES/时钟改相固有 | 违例端点是否集中在 SERDES | `cdc-and-signoff.md` §4 |
| "仿真 PASS" 但不可信 | 判据/覆盖/同源 | 参数覆盖、FAIL 行数、素材尺寸 | `verification-charter.md` §3 |
| 上电很久才出图 / 最后一张回第一张卡住 | 全卡顺序扫描 | 扫描上限 vs 目录范围 | `symptom-playbook.md` §7 |

## 5. 五道判定门（Gate）

上板/交付前逐门过，任何一门不过就不许说"完成"。

| 门 | 判据 | 工具 |
|---|---|---|
| G1 静态门 | 无常量截断、无恒 0/恒 1 占位、无未用输入 | `scripts/rtl_const_check.py` |
| G2 仿真门 | 每条 TB 有结构化 `RESULT`，FAIL/ERROR 计数为 0，参数覆盖在 `xelab` 中可见 | `scripts/check_sim_logs.py` |
| G3 时序门 | WNS ≥ 0 且 WHS ≥ 0，违例端点已归类（CDC/扇出/SERDES） | `scripts/check_timing.py` |
| G4 资源门 | LUT/FF/BRAM/DSP 在预算内，且有余量给后续改动 | `scripts/check_util.py` |
| G5 交付门 | 原件哈希未变；bit 与 RTL 版本对应；报告含失效条件 | `scripts/verify_manifest.py` |

> G3 的坑：Vivado 会在 WPWS 为负时打印 "Timing constraints are not met."，
> 而 WNS/WHS 可能都是正的。此时**不要**直接把设计判死，先看违例端点是否集中在
> OSERDES/MMCM 的固有相位关系上——是则记录为已知项，否则才是真违例。

## 6. 交付物清单

```text

├─ src/             RTL + 约束 + IP（IP 用 xci/prj，保证可重生成）
```

## 8. 反模式（见到就停下）

- 现象没说清就开始改 RTL；
- 用"应该"、"可能"、"一般来说"代替测量；
- 一次提交三个修复，然后说"好了"；
- 报告里只有结论，没有判据和失败记录；
- 把 AI 的第一次回答当答案，而不是当**假设**去验证；
- 为了跑通仿真去改原件的 `localparam`，然后声称"不影响功能"。
