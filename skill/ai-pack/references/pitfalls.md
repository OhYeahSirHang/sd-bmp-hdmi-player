## A 语言与声明

### P01 常量位宽静默截断 【实测】

- 触发：`localparam [24:0] X = 25'd50_000_000;`（50e6 需要 26 bit）。
- 现象：综合/仿真/lint 全不报错，行为与注释不符（注释 1 s，实际 0.329 s）。
- 根因：Verilog 字面量按声明位宽取模截断，**不饱和、不报错**。`50_000_000 mod 2^25 = 16_445_568`。
- 排查：`scripts/rtl_const_check.py` 的 V1 规则；或手算 `2^(msb−lsb+1)` 与字面量比。
- 对策：位宽 ≥ 所需位数，或直接 `[31:0]`；SystemVerilog 用 `localparam int`。

### P02 `localparam` 无法被 TB 覆盖 【实测】

- 触发：TB 写 `dut #(.LONG_CNT(100))`，RTL 声明却是 `localparam`。
- 现象：编译通过（最多一条 warning），参数没生效，仿真要么跑几千万拍要么判据全错。
- 根因：`localparam` 按定义不可外部覆盖。
- 排查：看 `_xelab.txt` 有没有 `Compiling module x.y(PARAM=值)`；没有即未生效。
- 对策：不要改原件。用副本 / shadow 模块 / 层次化 `force`（见 `verification-charter.md` §1）。

### P03 位宽改动就是行为改动 【实测】

- 触发：为了能被 TB 覆盖，把 `[24:0]` 改成 `[25:0]` 并把 `localparam` 改 `parameter`。
- 现象：报告写"默认值不变、不影响功能"，实际生效值从 16,445,568 变成 50,000,000。
- 根因：只对比了字面量，没对比位宽；位宽决定字面量是否被截断。
- 排查：声明改动逐项对比 `{位宽, 符号, 默认值, 表达式}`，任一项变即行为变更。
- 对策：改动表加一列"是否改变上板行为"，行为变更必须单列一节。

### P04 死代码 / 占位线冒充"已实现" 【实测】

- 触发：接口名齐全，模块体内从未使用；或 `wire x = y && 1'b0;`。
- 现象：读接口清单以为功能都在，实际某按键/某模式根本不存在。
- 根因：接口先行、逻辑未跟进，`*>` 把 unused 警告吞掉。
- 排查：`rtl_const_check.py` 的 V2/V3；或统计每个 input 在体内的引用次数。
- 对策：把占位项写进"未实现清单"，不能出现在功能描述里。

### P05 有符号/无符号混用 【通用】

- 触发：偏移量、差值、坐标计算里混用 `integer` 与 `reg [N:0]`。
- 现象：负偏移变成巨大正数，画面跳到屏幕外或全黑。
- 排查：所有参与减法/比较的量，确认是否声明 `signed`；跨模块传递时位宽与符号一致。
- 对策：偏移统一用 `signed [N:0]`，比较前显式 `$signed()`；边界处饱和而不是回绕。

## B 验证方法

### P06 二值断言掩盖方向性错误 【实测】

- 触发：断言写成"输出 ∈ {黑, 原值}"、"非空即可"。
- 现象：状态机方向反了、遮罩极性反了，TB 依然 PASS。
- 根因：集合成员断言对"比例/单调性/顺序"零约束。
- 排查：对每个渐变/遮罩输出问一句"它应该是单调的吗"。
- 对策：渐变类断言 = 首值 + 末值 + 单调性 + 步长，四者缺一不可。

### P07 只读最后一行 `RESULT` 【实测】

- 触发：日志里几百条 `FAIL px`，最后一行 `PASS … maxerr=4 <= 4`。
- 现象：以为通过，其实是容差通过且明细被忽略。
- 排查：统计 `FAIL`/`ERROR` 行数并与结论对照（`check_sim_logs.py` 已内置）。
- 对策：报告"判据"列必须写数值与比较符，"精确"与"容差"禁止混用措辞。

### P08 模块级 PASS ≠ 整机可用 【实测】

- 触发：只给"容易测"的算法模块建了 TB。
- 现象：5 个模块 PASS，但 SD 初始化、DDR3、HDMI、CDC 从未被驱动。
- 排查：画覆盖矩阵，强制列出"未覆盖"列（`verification-charter.md` §4）。
- 对策：上板前必须有顶层冒烟 TB（复位释放 + 首帧 + 切换 + 超时）。

### P09 产物陈旧（.bit / 网表 / IP 缓存） 【实测】

- 触发：改了 RTL 只跑仿真，没重综合就下载。
- 现象：仿真 PASS、板子依旧，连续几轮"修了没用"。
- 排查：对比 RTL `mtime` 与 `.bit` 生成时间；看 build log 时间戳。
- 对策：交付清单写"这个 bit 对应哪次 RTL 改动"；不确定就标"陈旧"。

### P10 素材太小导致覆盖率虚高 【实测】

- 触发：用 16×12、单 MCU、单色块做测试图，只求快。
- 现象：PASS，但只覆盖了最简路径。
- 排查：把素材参数（尺寸、子采样、MCU 数、量化表）写进报告，与真实素材对比。
- 对策：至少两档素材：极小（快速回归）+ 接近真实（验收）。

### P11 只留一段日志 【实测】

- 触发：用 `*>` 把 `xvlog/xelab/xsim` 输出全冲进一个文件，事后只剩运行日志。
- 现象：无法回答"日志是不是当前源码产生的"、"有没有位宽/多驱动警告"。
- 对策：三段分别落盘（`assets/run_xsim.ps1` 已强制），审计可信度直接由"中"升"高"。

## C 设计与集成

### P12 多 bit 信号跨域直接打两拍 【实测·静态】

- 触发：`img_w[11:0]`、`x_off[10:0]` 从 50 MHz 域进 148.5 MHz 域。
- 现象：偶发几何错位；仿真几乎抓不到。
- 根因：2FF 只保证"最终稳定"，不保证多 bit 同拍一致。
- 对策：握手 / 异步 FIFO / "数据稳定 + 单 bit 有效标志"。

### P13 硬编码分辨率 【实测·静态】

- 触发：`if (x_cnt == 1920-1)`，且计数器只在 `data_req` 时自增。
- 现象：换分辨率或 `de` 定义变化后整体错位。
- 对策：分辨率走参数；计数器用行首标志/`de` 上升沿复位，别靠"数够 1920"。

### P14 3×3 窗口在边界处缺失 【实测·静态】

- 触发：`valid_win = col>=2 && row>=2`，边界直接输出"非边缘"。
- 现象：图像最上 2 行、最左 2 列恒黑。
- 风险：TB 照现状写断言，会把缺陷固化成"正确行为"。
- 对策：边界策略（复制/镜像/补零）显式实现并单测，报告写明"四周 2 px 黑边是已知限制"。

### P15 跨域复位不同步 【通用】

- 触发：复位信号直接进另一个时钟域。
- 现象：上电偶发不启动；不同板子概率不同。
- 对策：复位同步器（异步置位、同步释放），每个域各一个。

### P16 双缓冲换页没对齐 VSYNC 【通用】

- 触发：CPU/状态机随时切换 ping-pong 地址。
- 现象：撕裂，切点逐帧游走。
- 对策：换页只在 VSYNC 后的消隐窗口内发生，用单周期脉冲触发。

### P17 换源时写侧 FIFO 未 flush 【实测】

- 触发：`frame_sync` 只清了 h/v，没清写 FIFO。
- 现象：新源从 h=0 写，旧残留把画面顶掉 N 个像素 → 整块右移。
- 对策：`frame_sync` 后 flush 固定拍数（如 31 个 ui_clk），确保指针归零。

### P18 偏移量在切换时残留 【实测】

- 触发：缩放/过渡模块里的 `rd_off` 在媒体切换时未清。
- 现象：切一次偏一点，多次切换后越偏越多。
- 对策：切换时统一清 `state/rd_off/swap_allow/first_done`，并加断言"首像素 x==0"。

### P19 "发出切换"≠"对方接受" 【实测】

- 触发：顶层用原始按键信号触发清 h/v，而下游播放器正在读帧、直接忽略了这次切换。
- 现象：当前帧被中途清掉行列计数，偏移/撕裂随机出现。
- 对策：加接受确认（`*_ack`），只有下游真正接收才执行清帧动作。

### P20 `ram_style="block"` 未生效 【实测】

- 触发：给行缓冲加了属性，但综合后 LUT 暴涨、BRAM 没变。
- 现象：资源报告与预期不符，时序变差。
- 根因：读口多于 1 个、或数组被拆成多个小阵列，推断失败。
- 排查：`report_utilization` 看 `LUT as Memory` 是否异常高；看综合日志的推断提示。
- 对策：改成单读口 + 寄存器打拍，或显式例化 BRAM IP。

## D 存储与素材

### P21 索引表范围 < 扫描范围 【实测】

- 触发：扫描上限写 100 MB，catalog 上限写 32 MB。
- 现象：无索引版能扫到全部图片，索引版只能找到前几张。
- 排查：`表内条目数 < 实际文件数` ⇒ 截断；用 `timing-budget.md` §5 反推数量级。
- 对策：两个上限必须同一个常量（`CATALOG_END == STOP_ADDR`），并加编译期断言。

### P22 文件没从扇区 0 裸写 【实测】

- 触发：把视频文件拖进 FAT32 分区。
- 现象：播放器按固定扇区号读，读到的是分区表/目录区。
- 对策：README 写明"从扇区 0 裸写"；生成脚本打印写入的起始扇区；dump 前 16 B 自检。

### P23 帧长不是 512 的整数倍 【通用】

- 触发：`W×H×2 + 头` 不能被 512 整除。
- 现象：最后一块读多/读少，末行花屏或整帧错位。
- 对策：帧长补齐（padding）到 512 整数倍，头里写"有效字节数"而不是"帧长"。

### P24 行缓冲撑不住源端抖动 【实测】

- 触发：4 行行缓冲 ≈ 2.5 KB，SD 单次命令间隔可达毫秒级。
- 现象：视频行内重复/拉丝/黑块，随卡的质量变化。
- 排查：`timing-budget.md` §4.2 算 `t_hold`；若 < 源端最长停顿即为不足。
- 对策：加大 FIFO（16 KB 级）/ 整帧双缓冲 / 主动降源端时钟让生产贴住消费。

### P25 像素格式顺序（BGR vs RGB） 【实测】

- 触发：BMP 按 BGR 存储，RGB565 打包时按 RGB 取。
- 现象：红蓝互换，肤色发蓝，纯色测试图立刻看出来。
- 对策：通道顺序只在**一处**修正（打包模块），不要在多个模块各修一半。

## E 环境与流程

### P26 PowerShell 执行策略被误判为"没权限" 【实测】

- 触发：Windows + 组策略把 ExecutionPolicy 设为 Restricted/AllSigned。
- 现象：工具调用直接失败，报 `无法加载文件 …prepare-workspace.ps1，因为在此系统上禁止运行脚本`，
  `+ FullyQualifiedErrorId : UnauthorizedAccess`。
- 关键鉴别：`SecurityError / UnauthorizedAccess` = **执行策略**；
  `[sandbox: file access denied]` = 沙箱拒绝。两者解法完全不同。
- 对策：最小探针 `Write-Output ok` 先判断是否进了命令；`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`；
  组策略需管理员；实在不行就在报告里写"本轮只有静态结论"，不要用旧日志冒充新结果。

### P27 用 `false_path` 盖住整条跨域路径 【实测】

- 触发：为了消掉 −4.7 ns，对整片寄存器加 `false_path` 或对整模块设异步时钟组。
- 现象：时序"通过"，真 bug 被藏起来，上板偶发错位。
- 对策：只约束同步器入口（见 `cdc-and-signoff.md` §2）；加完约束后违例**路径应消失**。

### P28 WHS 余量过小 【实测】

- 触发：为了抢 WNS 过度优化数据路径，保持时间只剩 0.01 ns 级。
- 现象：换批次/换温度后偶发错误；签核勉强通过。
- 对策：WHS 目标 ≥ 0.05 ns；不足时优先降时钟或加流水，不要靠工具"再跑一次"。
