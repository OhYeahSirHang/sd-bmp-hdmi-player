# 验证章程：怎么让"PASS"可信

> 一句话：**PASS 不是结论，PASS 是"在____判据下、用____素材、覆盖了____，通过"。**
> 三处空白填不出来，这个 PASS 就不能写进报告。

---

## 1. 只读验证章程（验证别人的工程时强制）

用户说"验证一下，但别改我的东西"时，按这五条执行：

1. **先快照**：`python scripts/verify_manifest.py --root <proj> --save baseline.json`
2. **只在副本上工作**：`proj_work/`，原目录一个字节都不动
3. **要在副本里改原件才跑得通时**：用 shadow 模块 / 层次化 `force` / 复制后改路径，
   **不改原文件**；确实必须改，先备份成 `*.orig` 并在报告里逐条列出
4. **收尾三件事**：
   - `verify_manifest.py --check baseline.json` 证明原件未变（差异必须为空）；
   - 列出"本次验证改过哪些副本文件"，以及每处改动**是否改变上板行为**；
   - 明确写"结论来自副本，原件未验证"
5. **不许用旧日志冒充新结果**：日志的时间戳必须晚于最后一次 RTL 改动。

---

## 2. 分阶段 TB：整机搭不起来时

把设计按"能独立驱动"切段，每段一个 TB，各自产出结构化结论：

```text
Stage 1  SD 命令层    CMD0/CMD8/CMD17/CMD18 时序与 CRC
Stage 2  数据搬运    扇区→行缓冲→DDR3 写 burst 对齐
Stage 3  显示时序     1080p 行场计数、DE、同步极性
Stage 4  图像处理     各模式的黄金参考比对
Stage 5  顶层冒烟     复位释放→首帧出图→按键切换→不卡死
```

**切分原则**：切完后每段都能用"喂激励 → 看输出"的方式驱动，不需要真实 SD 卡或显示器。
**判据**：任一 Stage 失败，能直接指名是哪个模块，而不是"整机不对"。

**TB 输出约定**（脚本 `check_sim_logs.py` 依赖这个格式）：

```verilog
$display("=== RESULT: PASS swaps=%0d fps=%0d ===", nswap, fps);
// 或
$display("=== RESULT: FAIL reason=offset_after_switch got=%0d exp=0 ===", x0);
```

没有 `=== RESULT:` 行的 TB，一律按"无结论"处理——这是有意为之，
因为"跑完没报错"不等于"验证过"。

## 3. 日志审计三问

拿到任何"已验证"的结论，先问这三句：

**Q1：这份日志是当前源码产生的吗？**

- 看 `_xelab.txt` 里有没有 `Compiling module <lib>.<mod>(PARAM=值)`；
- 若 TB 覆盖了某个参数，而源码里那个常量是 `localparam`（不可覆盖），
  则日志必然来自**改过的源码**；
- 看日志时间戳 vs 源码 `mtime`。

**Q2：判据是精确还是容差？**

- 搜结论原文里的 `maxerr`、`<=`、`tolerance`、`diff`；
- 统计 `FAIL` / `ERROR` 行数与结论是否矛盾
  （真实案例：300+ 条 `FAIL px` 明细，最后一行 `PASS … maxerr=4 <= 4`）；
- "容差通过"要写明容差值和依据，不能写成"一致"。

**Q3：覆盖了什么、没覆盖什么？**

- 画覆盖矩阵，**必须有"未覆盖"列**，空行不可信；
- 素材参数写进报告：尺寸、子采样、单/多 MCU、是否渐进；
- 拿 16×12 的单色块图跑通，不能代表 1080p 真实素材。

---

## 4. 覆盖矩阵模板

| 子系统 | 已覆盖 | 手段 | **未覆盖** | 风险 |
|---|---|---|---|---|
| SD 命令层 | CMD17 / CMD18 / CMD12 | 行为级模型 TB | 真实卡的热插拔、坏块重试 | 中 |
| DDR3 通路 | 写 burst 对齐、双缓冲换页 | 仿真 | MIG 校准失败、温度漂移 | 高（IP 黑盒） |
| 显示时序 | 1080p60 行场计数 | 计数断言 | 显示器兼容性/EDID | 低 |
| 图像处理 | 3 种模式黄金比对 | 逐像素 diff | 其余 14 种模式 | 中 |
| CDC | 静态审查 | 人工过一遍 | 亚稳态概率性事件 | 高（无法仿真） |

**读法**：风险列里"高"且"未覆盖"的项，就是上板时最可能咬你的地方，必须安排 ILA 观测点。

---

## 5. 冒烟 TB 的最低要求（上板前最后一关）

1. 复位释放后 N 个周期内必须出现第一个有效行同步（否则判死）；
2. 连续出 3 帧，帧间隔稳定（抖动 < 1 行）；
3. 跑一次"切媒体"动作，切换后首帧首像素坐标正确；
4. 全局超时：`T_MAX` 内没有进展就 `$fatal`（防止仿真"跑着但没动"）。

---

## 6. 可信度分级（报告里必须标）

| 等级 | 条件 |
|---|---|
| **高** | 三段日志齐全 + 结构化判据 + 覆盖矩阵无空行 + 产物与源码版本对应 + 上板复测 |
| **中** | 仿真通过但未上板，或上板通过但无仿真 |
| **低** | 只有静态阅读 / 只有一段日志 / 判据是"看起来对" |

报告结论旁边写等级，比写"已验证"有用得多。
