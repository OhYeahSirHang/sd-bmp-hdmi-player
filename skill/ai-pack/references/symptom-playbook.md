# 症状 → 假设 → 证据 → 修复

> 每个条目按固定四段写：**怎么认**（现象指纹）、**先怀疑谁**（按概率排序）、
> **要什么证据**（能证伪的最小观测）、**怎么修**（最小改动 + 回归项）。
> 带 `案例` 标记的是真实工程里发生过的，数字可直接复用。

---

## 1. 帧率低于目标，且是整数档（12 / 10 / 7.5）

**怎么认**：OSD 显示的 fps 长期稳定在某个整数档，不随画面内容变化；不是"偶尔掉帧"。

**先怀疑谁**

1. VSYNC 分频量化（`fps = 60/N`）——最常见；
2. 每帧读卡时间刚好越过一个档位边界；
3. 生成时间（像素数/像素时钟）本身就超了目标帧周期。

**要什么证据**：把目标帧周期、实测帧周期、`t_gen`、`t_read` 四个数写在一行里。
只要"实测 ∈ 区间 (1000/(fps+1), 1000/fps]"成立，就确认是量化而不是抖动。

**怎么修**（按代价从低到高）

1. 降 `t_read`：单块读改多块读（CMD17→CMD18 + CMD12），摊薄命令开销；
2. 调源端时钟：读卡时钟从 50 MHz 降到 25 MHz 反而更稳（限速匹配消费速率）；
3. 改节流策略：每 N 个 VSYNC 换一帧，N 由预算决定，不要写死"越多越稳"；
4. 若 `t_gen` 本身就超：减少每帧像素（缩放输出）或提高像素时钟。

> `案例`：目标 15 fps、实测 12 fps。`1080p / 50 MHz = 41.47 ms` 生成 +
> 300 次 CMD17 读卡，每帧越过 66.67 ms，落进 `60/5 = 12`。
> 修法：CMD18 一次读 300 块 + 视频读降 25 MHz + 每 4 个 VSYNC 换帧。
> 回归项：仿真必须打印 `RESULT swaps=17 fps=15` 且 `PACING_OK`。

## 2. 切换媒体/下一段之后，画面整块右移或上移

**怎么认**：偏移是"整块平移"，不是撕裂、不是局部错位；只在**切换之后**出现，
复位后恢复正常；偏移量每次基本一致。

**先怀疑谁**

1. 写侧 FIFO 里残留上一路的像素，新帧从 h=0 写时被顶掉 N 个像素 → 表现为右移；
2. 显示侧的偏移量（如 `rd_off`）在切换时没有清零，累计到下一路；
3. 切换信号与换页节拍不一致：顶层用"原始按键"触发清 h/v，而播放器实际没接受这次切换，
   于是当前帧被中途清掉行列计数。

**要什么证据**：抓三个信号在切换瞬间的值：`frame_sync`、写 FIFO 的 `wr_cnt`/`rd_cnt`、
`rd_off`（或等效偏移寄存器）。判据：切换后第一个像素周期，`wr_cnt` 应为 0 且 `rd_off` 为 0。

**怎么修**

1. `frame_sync` 到达后 **flush 写 FIFO**（给固定拍数，如 31 个 ui_clk，保证指针归零）；
2. 切换时清过渡/缩放模块的 `state / rd_off / swap_allow / first_done`；
3. 引入**接受确认**：`vid_next_ack` —— 只有播放器真正接收了"下一段"，顶层才发 `frame_sync`；
4. 回归项：新增断言"切换后首行首像素的 x 坐标 == 0"。

> `案例`：视频下一段后回图片，图片整块右移。三处同时存在：FIFO 未 flush、
> `img_trans` 的 `rd_off` 未清、顶层用原始 `vid_next` 触发 `frame_sync`。
> 只修其中一处时现象"减轻但没消失"——这正是"一次只改一个变量"的反面教材。

## 3. 撕裂：上下半屏新旧内容不一致

**怎么认**：画面在某一水平线处被"切开"，上半是旧帧、下半是新帧，切点位置逐帧游走。

**先怀疑谁**

1. 换页（双缓冲切换）发生在**扫描进行中**，而不是 VSYNC 消隐期；
2. 单缓冲 + 读改写同一片 DDR3，读写指针追尾；
3. 换页地址寄存器的跨域握手不完整（见 §10）。

**要什么证据**：记录换页信号与 VSYNC 的相位差。判据：换页必须落在 VSYNC 后固定的消隐窗口内；
若换页时刻随机分布，就是这里。

**怎么修**：换页动作绑定 VSYNC 边沿（两级同步 + 单周期脉冲），且在消隐期内完成；
双缓冲用 ping-pong 地址，禁止"写一半就切"。

## 4. 花屏 / 斜纹 / 彩色噪点

**怎么认**：整屏或大面积像素值错乱，但行列结构还在；有时呈 45° 斜纹。

**先怀疑谁**

1. 像素格式不匹配：BMP 是 BGR 排列、RGB565 期望 RGB，红蓝互换；
2. 采样沿/相位错：数据在错误的时钟沿被打入，形成逐像素 1 bit 错位（斜纹）；
3. 位宽截断：24 bit → 16 bit 时低位丢失（渐变出现色带，不是花屏）；
4. DDR3 写 burst 未对齐（128 bit 边界），出现"错位一个 beat"。

**要什么证据**：用纯色测试图（红/绿/蓝/灰阶各一张）定位。
判据：纯红显示成蓝 ⇒ 通道顺序；灰阶出现规律斜纹 ⇒ 相位；只在渐变处出现色带 ⇒ 位宽。

**怎么修**：通道顺序在打包处一次修正（不要在多个模块里各修一半）；
相位问题先降时钟验证，再查 IDELAY/采样沿；位宽问题按"高位对齐 + 舍入"处理，
不要简单截断低位。

## 5. 边缘/卷积模式出现规则点阵或斜向纹理

**怎么认**：只在某一种图像模式下出现，图案是等间距点阵/斜线；原图模式正常。

**先怀疑谁**

1. 3×3 窗口的行缓冲读地址步进错误（每行少读/多读一个像素，误差逐行累积成斜纹）；
2. 行缓冲深度不足，窗口在行边界处取到了上一行的残值；
3. 边界像素（前 2 行/列）没有定义，输出恒定值被误认为"图案"。

**要什么证据**：输入一张**纯色图**跑该模式。判据：纯色图的边缘输出应当全黑；
若出现点阵，就是地址/窗口问题而不是算法问题——这一步能在 5 分钟内排除一半假设。

**怎么修**：按"每行写指针 = 行首复位"重建行缓冲地址；边界显式实现（复制/镜像/补零）
并写进报告作为已知限制；回归项：纯色图 + 棋盘图 + 单像素点图三张。

## 6. OSD 文字错位 / 缺笔画 / 边缘偏色

**怎么认**：字是"歪的"或"少一笔"，不是完全没有；参数行与菜单行表现可能不同。

**先怀疑谁**

1. 字模 ROM 的位宽/寻址错（16×16 字模按 8 bit 取，右半边丢失）；
2. OSD 与图像的混叠优先级/alpha 处理错，半透明处出现脏边；
3. RGB565 量化：白色 (255,255,255) → (248,252,248)，细笔画边缘出现偏色，
   视觉上像"字发虚"——这是**量化误差**，不是 bug，要在报告里说明而不是"修"。

**要什么证据**：显示一张全白底 + 单字符的测试图。判据：字符笔画是否逐列完整；
若有整列缺失 ⇒ 寻址；若边缘一圈偏色 ⇒ 量化（正常）。

**怎么修**：字模按行/列连续寻址，一个字占 `16 × 16 bit = 32 B`；
混叠优先级写死为"OSD 覆盖图像"，不要用有符号比较。

## 7. 上电很久才出图 / 最后一张回到第一张卡住

**怎么认**：功能都对，就是"等"。首次出图前有一段固定长度的黑屏；从最后一张切回第一张
要等十几秒。

**先怀疑谁**

1. 逐扇区顺序扫描全卡找文件头（BMP 的 `BM`、或自造格式的 magic）；
2. 扫描上限 `STOP_ADDR` 远大于实际素材区；
3. 做了索引表，但 **catalog 范围 < 扫描范围**，导致表里只有前几张。

**要什么证据**：`扫描字节 / 有效带宽 = 预期耗时`，与实测对比（见 `timing-budget.md` §5）。
数量级一致 ⇒ 确认是扫描；表里条目数 < 实际图片数 ⇒ catalog 范围截断。

**怎么修**

1. 索引表：上电扫一次，记录每个文件头扇区，之后"下一张"直接跳表；
2. **catalog 范围必须覆盖完整扫描上限**（这是最容易漏的一条：扫描用 100 MB，catalog 只写 32 MB，
   结果只能找到前几张）；
3. 切媒体时不要把索引表一起复位（否则切回图片又重新扫）；
4. 若都不能接受，改文件系统解析（读 FAT 表），代价是实现复杂度。

> `案例`：offset 修复版能扫到全部图片，加索引表的版本只能扫到 2 张。
> 反推：32 MB 只够 5 张，实测 2 张 ⇒ 不是"扫描范围小"，是 catalog 上限写成了 32 MB。
> 改成 100 MB 后恢复。上电 catalog 约 17 s（100 MB / 6.25 MB/s ≈ 16 s，吻合）。

## 8. 视频完全不出图 / 切到视频无响应

**怎么认**：图片通路正常，切到视频后黑屏、卡住、或菜单无反应。

**先怀疑谁**

1. 文件格式与播放器预期不一致（头字段、帧长、像素排列）；
2. 文件没有从**扇区 0 裸写**，而是在 FAT32 分区里——播放器按扇区号找，自然找不到；
3. 探测逻辑（找 magic）与数据区重叠，把自己写进去的头当成了帧数据；
4. 帧长不是 512 的整数倍，最后一块读取长度错。

**要什么证据**：把 SD 卡前 4 个扇区 dump 出来看 magic；用已知正确的文件替换测试。
判据：dump 出的前 16 B 与生成脚本写的头**逐字节一致**。

**怎么修**：生成脚本与播放器共用一份格式定义（同一份常量），并在 README 写明
"从扇区 0 裸写，不要放进分区"；帧长补齐到 512 整数倍。

## 9. 放大/居中后位置不对（黑边不对称、整体偏）

**怎么认**：小分辨率视频放大到 1080p 后，左右黑边宽度不等，或整幅偏左/偏右。

**先怀疑谁**

1. 起始坐标算错：`x0 = (1920 − W×3)/2`，整数除法丢余数导致偏 1 px；
2. 缩放倍数与行缓冲读出速率不匹配，导致每行少/多一个像素；
3. 偏移量在模式切换时被继承（见 §2）。

**要什么证据**：用纯色 + 1 px 边框的测试图，量四边黑边像素数。判据：左右差 ≤ 1 px。

**怎么修**：起始坐标用 `(总宽 − 有效宽) >> 1` 并显式处理奇偶；缩放用整数倍 + 重复像素，
不要用非整数步进（会产生不均匀行）。

## 10. 偶发错位 / 一天出现几次的诡异现象

**怎么认**：仿真复现不了；换一块板/换温度/换批次出现概率不同；多是"几何参数突然错一下"。

**先怀疑谁**

1. **多 bit 信号跨时钟域直接打两拍**：某一位新、某一位旧，瞬间得到一个不存在的组合值；
2. 异步复位释放不同步（复位撤除时进入亚稳态）；
3. 组合逻辑跨域（没有寄存就过域）。

**要什么证据**：列出所有跨域信号，多 bit 的一律标红；用 ILA 抓跨域前后的值，
判据：是否出现"从未在源端出现过的组合"。

**怎么修**：多 bit 用握手 / 异步 FIFO / "数据稳定 + 单 bit 有效标志"；
单 bit 控制信号才允许两级同步；同步器入口加 `false_path`（见 `cdc-and-signoff.md`）。
